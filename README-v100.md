# 영종 디에트르 라 메르 v10.0

v10.0은 정식 운영 출시 후보 버전입니다. 관리자 비밀번호 노출 범위를 줄이고, 서버가 바뀌거나 네트워크 요청이 재시도되어도 같은 관심고객이 Google Sheets에 중복 저장되지 않도록 운영 안전성을 강화했습니다.

## 핵심 변경사항

### 관리자 로그인·개인정보 보호

- 관리자 비밀번호는 로그인할 때 한 번만 서버로 전송하고 이후 목록·번호 확인·상태 저장 요청에는 다시 포함하지 않습니다.
- 로그인 성공 시 15분 유휴 만료와 최대 8시간 절대 만료가 적용된 HMAC 서명 HttpOnly 쿠키를 발급합니다.
- 운영 쿠키에 `Secure`, `SameSite=Strict`, `HttpOnly`, `Path=/`, 높은 우선순위를 적용합니다.
- 모든 관리자 변경 요청에서 세션, 요청 출처(Origin), 메모리형 CSRF 확인값을 함께 검증합니다.
- 활동 중인 세션은 5분 간격으로 안전하게 연장하며, 15분 동안 사용하지 않으면 화면과 서버 세션을 함께 잠급니다.
- 수동 잠금은 `로그아웃·잠금`으로 표시하고 서버 쿠키까지 즉시 만료시킵니다.
- 세션이 만료되거나 요청 확인값이 일치하지 않으면 목록, 메모, 공개한 전화번호, CSV 대상 데이터를 즉시 화면에서 제거합니다.
- 로그인 성공 후 비밀번호 입력값을 바로 삭제하고, 새로고침 시 유효한 HttpOnly 세션만 복원합니다.

### Google Sheets 영구 중복 방지

- Google Sheets의 기존 열과 데이터는 유지하면서 오른쪽 끝에 `이벤트ID` 열을 자동 추가합니다.
- Apps Script의 잠금 구간 안에서 `이벤트ID` 조회와 신규 행 추가를 한 번에 처리합니다.
- 같은 신청이 재시도되면 새 행을 만들지 않고 기존 접수번호를 반환합니다.
- 같은 이벤트ID에 다른 전화번호가 들어오면 충돌 요청으로 거부합니다.
- 잘못된 이벤트ID, 시트 사용 중 상태, 접수번호 충돌을 구분해 응답합니다.
- 관리자 목록·개별 번호 조회는 전역 쓰기 잠금을 점유하지 않아 고객 접수와의 불필요한 경쟁을 줄였습니다.
- 기존 v9.9 요청처럼 `action` 값이 없는 저장 요청도 한 버전 동안 계속 받을 수 있어 배포 순서가 달라도 접수 중단을 줄입니다.

### 폼 제출 신뢰성

- 공식 신청 요청의 이벤트ID를 필수로 검증하고 허용 문자와 길이를 제한합니다.
- Google Sheets가 반환한 접수번호를 고객에게 표시하는 최종 접수번호로 사용합니다.
- Sheets에서 같은 이벤트ID가 이미 저장된 것으로 확인되면 성공으로 복구하되 문자와 광고 전환 후처리는 중복 실행하지 않습니다.
- 시트 잠금 경합 시 같은 화면에서 동일한 신청으로 재시도할 수 있도록 안내하고 `Retry-After`를 반환합니다.
- 연동 테스트 접수에도 고유 이벤트ID와 명시적인 저장 작업명을 적용했습니다.

### 모바일 관리자 화면·접근성

- 760px 이하에서는 가로 1,240px 표를 고객별 카드형 목록으로 전환합니다.
- 이름, 마스킹 전화번호, 상태, 상담 메모, 문자 상태, 저장 버튼을 한 카드 안에서 세로로 처리할 수 있습니다.
- 로그인 상태를 `확인 중`, `로그아웃`, `로그인 중`, `로그인 완료`로 분리해 비밀번호 화면 깜빡임과 상태 혼선을 줄였습니다.
- 관리자 로그인은 실제 폼 제출 방식으로 변경하고 로그인 실패 시 비밀번호 입력칸으로 초점을 돌립니다.

### 첫 화면 성능·SEO·운영 문구

- 첫 화면 영상은 페이지 로딩 완료 후 브라우저가 여유로운 시점에 연결해 초기 대표 이미지와 네트워크 경쟁을 줄였습니다.
- 데이터 절약 모드, 동작 감소 설정, 숨겨진 탭의 기존 보호 동작을 유지합니다.
- 이미지 사이트맵에 대표 이미지, 평면 6종, 단지배치도, 랜드마크, 시스템 이미지를 추가했습니다.
- 개인정보 안내의 내부 검토용 문구를 제거하고 동의 철회·상담 정보 문의 연락처로 교체했습니다.

## 배포 전 필수 작업

### 1. Google Apps Script 업데이트

`integrations/google-apps-script.gs`의 전체 내용을 기존 Apps Script에 덮어씁니다.

저장 후 다음 순서로 새 버전을 배포합니다.

```text
배포 → 배포 관리 → 수정 → 새 버전 → 배포
```

기존 웹 앱 주소와 스크립트 속성 `WEBHOOK_SECRET`은 그대로 사용합니다. 첫 신규 접수 때 기존 시트 오른쪽 끝에 `이벤트ID` 열이 자동 추가됩니다.

### 2. Vercel 환경변수 추가

기존 환경변수는 유지하고 아래 값을 추가합니다.

```text
ADMIN_SESSION_SECRET=32자-이상의-별도-임의-문자열
ADMIN_ALLOWED_ORIGINS=https://실제-운영-주소
```

- `ADMIN_SESSION_SECRET`은 관리자 비밀번호와 다른 값을 사용하세요. 비밀번호 관리 프로그램에서 40자 이상 임의 문자열을 만드는 방법이 가장 쉽습니다.
- `ADMIN_ALLOWED_ORIGINS`은 홈페이지를 실제로 여는 주소와 정확히 같아야 합니다.
- 대표 주소 하나만 사용하고 `NEXT_PUBLIC_SITE_URL`이 정확하다면 `ADMIN_ALLOWED_ORIGINS`을 비워도 해당 대표 주소를 사용합니다.
- `www` 주소와 비-`www` 주소를 모두 직접 사용한다면 쉼표로 구분해 둘 다 입력합니다.
- `ADMIN_DASHBOARD_TOKEN`, `NEXT_PUBLIC_SITE_URL`, Google Sheets·문자 환경변수는 기존 값을 유지합니다.
- 운영 Vercel에는 `LEAD_TEST_MODE`를 설정하지 마세요.

### 3. 재배포 후 확인

- 홈페이지에서 관심고객 1건 테스트 접수
- Google Sheets 오른쪽 끝의 `이벤트ID` 열과 신규 행 확인
- 담당자 문자 수신 확인
- `/admin` 로그인 후 비밀번호 입력줄이 사라지는지 확인
- 모바일 `/admin`에서 고객별 카드, 번호 보기, 상태·메모 저장 확인
- `로그아웃·잠금` 후 새로고침했을 때 다시 로그인이 필요한지 확인
- `/api/health` 버전 `10.0.0` 확인

## 운영 참고

- 기존 행은 이벤트ID가 비어 있으므로 v10.0 적용 이후 신규 접수부터 영구 중복 방지가 적용됩니다.
- 이 버전은 Google Sheets 행의 중복 저장을 막습니다. 저장 직후 서버 응답이 완전히 끊어진 매우 드문 상황에서는 문자 알림 재처리 여부가 별도 운영 확인 대상입니다.
- `ADMIN_SESSION_SECRET`을 변경하면 현재 로그인된 모든 관리자 세션이 즉시 무효화됩니다.
- Vercel 미리보기 주소에서도 관리자를 사용하려면 해당 정확한 주소를 `ADMIN_ALLOWED_ORIGINS`에 추가해야 합니다.
