# 영종 디에트르 랜딩페이지 v16.0

실제 광고 송출 후 문자 알림과 Meta 서버 광고전환을 중복 없이 처리하고, 성공·실패 상태를 관리자가 확인할 수 있게 만든 광고 운영 신뢰성 강화 버전입니다.

## 핵심 변경

- 접수 응답이 끊겨 고객이 같은 신청을 다시 보내더라도 문자 알림을 한 번만 처리합니다.
- Google Sheets가 문자와 Meta 전환 작업을 `대기 → 처리중 → 성공/실패`로 잠그며 중복 실행을 막습니다.
- Meta 전환 처리 중 서버가 종료되어도 5분이 지난 잠금은 같은 접수 재시도에서 자동 복구합니다.
- 문자가 `대기`·`처리중`·`실패`에 멈추면 중복 발송을 피하도록 자동 재전송하지 않고 관리자 확인 건수로 표시합니다.
- 같은 접수확인값으로 다시 시도하는 정상 재시도는 접수 횟수 제한에서 제외합니다.
- 모든 접수 API 응답에 요청 ID를 붙여 문제 발생 시 화면에서 바로 확인할 수 있습니다.
- Meta Conversions API 결과를 Google Sheets에 기록합니다.
- 관리자 화면에 광고전환 상태·주의 건수·필터를 추가했습니다.
- CSV 내려받기에도 광고전환 상태를 포함합니다.

## Google Sheets 추가 열

v16 Apps Script를 배포한 뒤 첫 접수 또는 연동 테스트 시 다음 열이 기존 시트 오른쪽에 자동 추가됩니다.

```text
광고전환상태
광고전환처리시각
광고전환상세
```

기존 고객 데이터와 기존 열은 그대로 유지됩니다.

## 광고전환 상태 의미

- `대기`: Meta 서버 전환 전송 예정
- `처리중`: 중복 방지 잠금 후 전송 중
- `성공`: Meta가 이벤트를 접수함
- `실패`: 전송 오류로 확인 필요
- `미설정`: Meta CAPI 환경변수를 사용하지 않음
- `미동의`: 방문자가 분석 사용에 동의하지 않아 전송하지 않음

`미설정`과 `미동의`는 오류가 아니며, 관리자 화면의 확인 필요 건수에서 제외됩니다.

## 안전한 적용 순서

1. v16 ZIP의 `integrations/google-apps-script.gs` 전체를 기존 Apps Script에 먼저 덮어씁니다.
2. `배포 → 배포 관리 → 수정 → 버전: 새 버전 → 배포`를 진행합니다.
3. v16 프로젝트 파일을 기존 GitHub Desktop 프로젝트에 덮어쓰고 Commit·Push합니다.
4. Vercel 배포가 `Ready`가 되면 `/system-check`에서 Google Sheets와 문자 테스트를 합니다.
5. 실제 스마트폰 번호로 홈페이지 신청을 한 번 완료하고 시트의 문자·광고전환 상태를 확인합니다.

Vercel 환경변수는 새로 추가할 항목이 없습니다. Meta CAPI를 사용하려면 기존 `META_PIXEL_ID` 또는 `NEXT_PUBLIC_META_PIXEL_ID`와 `META_CAPI_ACCESS_TOKEN`이 필요합니다.
