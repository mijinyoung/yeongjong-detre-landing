# 영종 디에트르 랜딩페이지 v9.0

## 목표

v9.0은 실제 운영 환경에서 접수 누락과 중복 시도를 줄이고, 관리자 사용성·접근성·SEO 설정 안정성을 강화한 버전입니다.

## 주요 변경사항

### 폼 제출 신뢰성

- Google Sheets 저장을 접수 성공 기준으로 명확히 분리했습니다.
- 문자 알림과 Meta 전환 전송은 저장 응답 이후 처리하여 외부 서비스 지연 때문에 고객 화면이 시간 초과되는 가능성을 줄였습니다.
- 문자 처리 결과는 기존처럼 Google Sheets의 배송 상태에 후속 반영됩니다.
- 네트워크 오류 후 다시 제출할 때 동일한 제출 식별자를 유지합니다.
- 동일 요청의 재전송은 중복 오류 대신 기존 접수번호와 정상 완료 응답을 반환합니다.
- 모든 신청 폼에 필수 입력, 최대 이름 길이, 전송 중 상태 표식을 추가했습니다.

### 접근성

- 내부 페이지 이동을 Next.js `Link`로 통일했습니다.
- 관리자 목록에 표 제목과 검색 입력 설명을 추가했습니다.
- 관리자 비밀번호 입력 도움말을 연결했습니다.
- 상담 모달의 설명·닫기 버튼 이름과 필수 입력 표식을 보강했습니다.
- 스크린리더 전용 공통 스타일을 추가했습니다.
- 분석 동의 상태 구독 방식을 개선하여 불필요한 연쇄 렌더링을 제거했습니다.

### 관리자 및 운영 점검

- 관리자 API 응답에 `no-store`를 적용하여 고객 목록이 브라우저나 중간 캐시에 남지 않도록 했습니다.
- 관리자 API가 비정상 응답을 반환할 때 사용자에게 이해할 수 있는 오류를 표시합니다.
- 운영 상태 API에도 `no-store`를 적용하고 표시 버전을 `9.0.0`으로 갱신했습니다.
- 관리자·운영 점검 화면의 린트 오류와 사용하지 않는 코드를 정리했습니다.

### SEO 설정 안정성

- 대표 사이트 주소를 한 곳에서 검증·정규화하도록 통합했습니다.
- 잘못된 `NEXT_PUBLIC_SITE_URL`이 빌드 또는 메타데이터 생성을 중단시키지 않도록 안전한 기본 주소를 사용합니다.
- 레이아웃, 구조화 데이터, robots, sitemap이 동일한 대표 주소를 사용하도록 정리했습니다.

## 의존성 보안 참고

`npm audit --omit=dev`는 Next.js 16.2.12에 포함된 `postcss`와 `sharp` 전이 의존성에서 High 3건을 보고했습니다. 감사 도구가 제시한 자동 수정은 Next.js 9.3.3으로의 비호환 다운그레이드이므로 적용하지 않았습니다. Next.js에서 호환되는 상위 의존성 조합을 제공할 때 별도 업데이트가 필요합니다.

## 배포 전 확인

- Vercel의 `NEXT_PUBLIC_SITE_URL`은 실제 서비스 주소 전체(예: `https://example.com`)로 설정합니다.
- `GOOGLE_SHEET_WEBHOOK_URL`, `WEBHOOK_SECRET`, 문자 발송 환경변수, `ADMIN_DASHBOARD_TOKEN`이 Production 환경에 유지되어 있는지 확인합니다.
- 배포 후 실제 전화번호로 관심고객 접수 1건을 진행하고 Google Sheets 저장 및 문자 상태 갱신을 확인합니다.
