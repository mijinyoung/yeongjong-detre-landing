# 현장 복제형 광고 랜딩페이지 v11.0

v11.0은 영종 디에트르 사이트의 운영 기능을 유지하면서 여러 분양 현장을 빠르게 복제할 수 있도록 현장 정보와 광고 콘텐츠를 한 곳에 모은 버전입니다.

## 핵심 변경사항

### 한 곳에서 현장 전체 교체

`data/project-content.json`에서 다음 내용을 관리합니다.

- 현장명, 브랜드명, 지역명
- 대표 전화번호와 전화 연결값
- 브라우저·공유·검색 SEO 정보
- 메인 영상, 포스터, 대표 이미지
- 메인 제목·설명·핵심 장점·요약 수치
- 사업개요, 입지, 프리미엄, 커뮤니티
- 분양 안내, 개발 일정, 공식자료
- 평면 타입, 영상 목록, FAQ
- 법적 고지, 개인정보 목적·보유기간
- 현장코드, 접수번호 접두사, 문자 제목
- 현장별 색상과 섹션 노출 여부
- PC·모바일 메뉴

전화번호, 현장명, SEO 제목처럼 여러 파일에 흩어져 있던 값은 설정 파일을 참조하도록 변경했습니다.

### 자료가 없는 섹션 숨김

`display` 항목에서 영상·평면·공식자료·입지·FAQ 등 각 섹션을 `true` 또는 `false`로 선택할 수 있습니다. 새 현장에 특정 자료가 아직 없으면 해당 섹션을 숨긴 상태로 먼저 제작할 수 있습니다.

메뉴 항목은 `navigation`에서 별도로 켜고 끌 수 있습니다. 숨긴 섹션으로 이동하는 메뉴가 남지 않도록 같이 확인해 주세요.

### 여러 현장 접수 구분

- 서버가 모든 신규 접수에 `현장코드`와 `현장명`을 자동 추가합니다.
- Google Sheets에 `현장코드`, `현장명` 열을 자동 추가합니다.
- 문자 알림에 현장명을 표시합니다.
- Meta 전환 데이터에 현장코드와 현장명을 포함합니다.
- 관리자 목록·번호 확인·상태 저장은 현재 설정의 현장코드 범위로 제한합니다.
- 현장마다 접수번호 접두사를 다르게 지정할 수 있습니다.

같은 Google Sheets를 여러 현장이 공유하더라도 현재 현장 관리자 화면에는 해당 현장의 문의만 표시됩니다. 현장별로 완전히 분리해 운영하려면 Apps Script와 시트를 각각 배포해도 됩니다.

### 복제 전 자동 검사

`npm run project:check`가 다음 항목을 검사합니다.

- 필수 현장 정보와 전화번호
- 현장코드·접수번호 형식
- SEO 개발용 주소 형식
- 표시 설정과 메뉴 형식
- 중복된 입지·공식자료·평면·영상 ID
- 설정에 연결된 이미지·영상 파일 존재 여부
- 임시 문구 잔존 여부
- Google Apps Script 현장코드·버전 일치 여부

`npm run verify`는 현장 설정 검사, TypeScript, ESLint, 프로덕션 빌드를 순서대로 실행합니다.

## 새 현장 복제 순서

1. 이 프로젝트 폴더를 새 현장명으로 복사합니다.
2. `PROJECT-MATERIALS-TEMPLATE.md`의 자료를 준비합니다.
3. `data/project-content.json`을 새 현장 정보로 교체합니다.
4. `public/images`, `public/videos`에 새 자료를 넣고 설정의 경로를 맞춥니다.
5. `integrations/google-apps-script.gs` 상단의 `PROJECT_CODE`, 필요 시 `SHEET_NAME`을 변경합니다.
6. `npm run project:check`를 실행합니다.
7. Vercel 환경변수와 실제 도메인을 새 현장 기준으로 설정합니다.
8. TypeScript, ESLint, 프로덕션 빌드를 통과한 뒤 배포합니다.

현장 자료를 전달하면 2~5번을 기준으로 바로 교체 작업을 진행할 수 있습니다.

## Google Apps Script 업데이트

v10에서 v11로 올릴 때는 `integrations/google-apps-script.gs` 전체를 기존 Apps Script에 덮어쓰고 새 버전으로 배포합니다.

```text
배포 → 배포 관리 → 수정 → 새 버전 → 배포
```

기존 시트의 열과 자료는 유지됩니다. 신규 접수 시 누락된 `현장코드`, `현장명` 열이 오른쪽 끝에 자동 추가됩니다. 기존 행에는 현장코드가 없으므로 v11 적용 이후 접수부터 현장별 관리자 필터에 표시됩니다.

## Vercel에서 현장별로 확인할 값

- `NEXT_PUBLIC_SITE_URL`: 새 현장의 실제 HTTPS 주소
- `ADMIN_ALLOWED_ORIGINS`: 새 현장의 관리자 허용 주소
- `GOOGLE_SHEET_WEBHOOK_URL`: 새 Apps Script 또는 공유 Apps Script 주소
- Google Sheets 웹훅 인증값
- SOLAPI 또는 문자 웹훅 설정
- Meta Pixel·전환 API
- Google Analytics / Google Ads
- 관리자·운영 점검 비밀번호

`ADMIN_SESSION_SECRET`, API 키, 비밀번호는 현장 자료나 ZIP에 포함하지 않습니다.

## 운영 배포 확인

- PC·모바일 메인 화면과 영상 재생
- 모든 전화 버튼의 대표번호
- 관심고객 1건 테스트 접수
- Google Sheets의 현장코드·현장명·이벤트ID
- 담당자 문자에 표시된 현장명
- `/admin`에서 현재 현장 문의만 표시되는지
- `/api/health` 버전 `11.0.0`
- 카카오톡·SNS 공유 이미지와 제목
- 숨긴 섹션과 메뉴가 함께 제거됐는지

## 검증 결과

- 현장 설정·필수값·이미지·영상 경로 검사 통과
- TypeScript 검사 통과
- ESLint 오류·경고 없이 통과
- Next.js 16.2.12 프로덕션 빌드 통과
- 정적 페이지 17개 생성 확인
- 로컬 운영 서버에서 홈페이지·관리자 페이지 HTTP 200 확인
- 홈페이지의 현장명·전화번호·현장코드 출력 확인
- `/api/health` 버전 `11.0.0` 확인
- 현장 설정이 반영된 manifest·이미지/영상 sitemap 확인

로컬 브라우저 자동 화면 조작은 실행 환경의 로컬 주소 사용 제한으로 생략했습니다. 코드·빌드·HTTP 응답 검증은 완료했으며 실제 배포 후 위의 PC·모바일 운영 확인 항목을 한 번 점검하세요.
